작성 기준일: 2026-10-07
적용 대상: lc-backend 의 develop 브랜치
관련 문서: [런치캐치_프론트엔드_배포와_도메인.md](./런치캐치_프론트엔드_배포와_도메인.md), [백엔드공통_장애대응목표와_아키텍처결정.md](./백엔드공통_장애대응목표와_아키텍처결정.md) (`INF-45`)

develop 에 병합된 코드를 실제 서버에서 프론트와 함께 확인하는 곳이다. 운영과 같은 구조를 재현하는 곳이 아니다.

## 1. 무엇을 정했나

| 항목 | 결정 |
|---|---|
| 구성 | EC2 `t3.medium` 1대에 앱, MySQL 8.4, Valkey 9.0, Caddy, Prometheus, Grafana 를 Docker Compose 로 함께 띄운다 (2026-10-21 `t3.small` 에서 올림, 11장) |
| 위치 | 전용 VPC 와 퍼블릭 서브넷 하나. NAT 없음 |
| 주소 | 백엔드 `api.dev.lunchcatch.com`. 프론트 `dev.lunchcatch.com`, `owner.dev.lunchcatch.com`, `admin.dev.lunchcatch.com` |
| HTTPS | 서버 안의 Caddy 가 인증서를 자동으로 받는다 |
| 배포 | lc-backend develop 병합 시 GitHub Actions 가 자동으로 |
| 가동 | 필요할 때만. 운영과 따로 올리고 내린다 |
| 관리 | Terraform 새 루트 `dev/`. 배포 역할과 이미지 저장소는 `bootstrap/` |

## 2. 왜 이 구성인가

세 가지를 견줬다.

| 안 | 월 비용 (상시) | 버린 이유 |
|---|---|---|
| **단독 서버 1대** | 약 25 USD | 채택 |
| 운영 축소판 (같은 Terraform 을 한 벌 더) | 약 100~130 USD | 개발 서버의 목적에 비해 비싸다. Terraform 을 환경별로 나누는 큰 작업이 든다 |
| 운영 인프라 공유 (운영 ALB 와 RDS 를 함께) | 약 20~40 USD | 개발 서버의 부하와 실수가 운영 DB 와 ALB 에 닿는다 |

**개발 서버의 목적은 "develop 의 기능이 실제 서버에서 프론트와 함께 도는가" 다.** 운영과 같은 구조가 필요한 검증(장애 주입, 롤링 배포, 부하 시험)은 운영 인프라를 올렸을 때 한다.

### 2.1 운영과 다른 점

의도한 차이다. 개발 서버에서 아래를 확인하지 않는다.

| 운영 | 개발 서버 |
|---|---|
| ALB, ASG 롤링 배포, 앱 2대 이상 | 서버 1대. 배포는 재시작이라 몇십 초 끊긴다 |
| RDS Multi-AZ, ElastiCache 2노드 | 같은 서버의 MySQL 과 Valkey 컨테이너 |
| 배치 서버 2대 액티브-액티브 | 앱이 `batch` 프로필로 떠서 스케줄러도 같은 프로세스에서 돈다 |
| 모니터링 서버, 알람 | 없다 |
| S3 와 CloudFront 이미지 저장소 | 있다. 버킷 `lunchcatch-dev-media`, 주소 `https://cdn.dev.lunchcatch.com`. 서버를 내려도 남도록 `bootstrap/dev_media.tf` 가 갖는다 |
| 시드 데이터 (lc-backend `db/seed`) | 켠다(`SEED_ENABLED=true`). 시드 계정 비밀번호는 저장소에 공개된 기본값 `lunchcatch1234!` 이다 (2026-10-16) |

## 3. 네트워크와 주소

운영 VPC 에 넣지 않는다. 운영은 `destroy.sh` 로 통째로 내리는데, 그 위에 개발 서버를 두면 함께 사라진다.

| 무엇 | 값 |
|---|---|
| VPC | `10.10.0.0/16`. 운영(`10.0.0.0/16`)과 겹치지 않게 |
| 서브넷 | 퍼블릭 하나 (AZ a) |
| 인바운드 | 80, 443. 80 은 Caddy 의 인증서 발급과 HTTPS 리다이렉트용 |
| 운영 접근 | SSM Session Manager. 22 번은 열지 않는다 |
| 주소 | 고정 IP(EIP). `api.dev.lunchcatch.com` A 레코드가 가리킨다 |

**NAT 를 두지 않는다.** 서버가 퍼블릭 서브넷에 있어 바로 나간다. NAT 는 월 43 USD 다. 보안은 보안 그룹(80, 443 만)과 Caddy 가 앞에 서는 것으로 한다. 앱(8080), 액추에이터(8081), MySQL, Valkey 는 밖에 열지 않는다.

### 3.1 주소 이름

운영 주소에 `dev.` 를 끼운다. 주소만 보고 환경을 안다.

| 앱 | 운영 | 개발 |
|---|---|---|
| 사용자 | `lunchcatch.com` | `dev.lunchcatch.com` |
| 점주 | `owner.lunchcatch.com` | `owner.dev.lunchcatch.com` |
| 관리자 | `admin.lunchcatch.com` | `admin.dev.lunchcatch.com` |
| 백엔드 | `api.lunchcatch.com` | `api.dev.lunchcatch.com` |

개발 프론트와 개발 API 가 같은 사이트(`lunchcatch.com`)라 `SameSite=Strict` 쿠키로 로그인이 된다 (프론트엔드 배포 문서 2.1절).

**대가: 개발과 운영도 같은 사이트다.** 운영에 로그인한 브라우저로 개발 프론트를 열면, 개발 프론트의 코드가 운영 API 를 그 사용자의 운영 쿠키로 부를 수 있다. 쿠키 값은 읽지 못한다(`HttpOnly`). develop 에는 리뷰 전 코드가 들어갈 수 있으니 이론상 경로가 있다.

**전제: 개발 서버는 팀원만 쓴다.** 실서비스로 키우면 개발 환경을 다른 도메인(예: `lunchcatch-dev.click`)으로 옮긴다.

## 4. 서버 안

```
Caddy (80, 443)  ->  app (8080)  ->  mysql (3306), valkey (6379)
```

| 컨테이너 | 이미지 | 메모리 상한 | 비고 |
|---|---|---|---|
| caddy | `caddy:2` | 64 MB | `api.dev.lunchcatch.com` 의 인증서를 받고 app 으로 넘긴다 |
| app | 개발 ECR `lunchcatch-dev:<SHA>` | 1,100 MB | `SPRING_PROFILES_ACTIVE=batch`. 힙은 상한의 70% |
| mysql | `mysql:8.4` | 512 MB | `innodb_buffer_pool_size=128M`, `performance_schema=OFF` |
| valkey | `valkey/valkey:9.0-alpine` | 128 MB | `maxmemory 64mb` |

`t3.medium` 은 메모리가 4 GB 다(처음에는 `t3.small` 2 GB). 컨테이너마다 상한을 모두 건다. 상한이 없으면 JVM 이 호스트 메모리 기준으로 힙을 잡아 MySQL 과 다투다 커널 OOM 으로 죽는다(운영 미결정 2.1.1 의 교훈). 여유로 스왑 2 GB 를 둔다.

**프로필이 `batch` 인 이유.** 서버가 하나라 API 와 스케줄러를 한 프로세스에서 돌린다. `batch` 프로필이 스케줄러를 켜고 풀을 5 로 둔다. 개발 서버의 요청량에는 충분하다.

## 5. 시크릿

| 값 | 어디 | 운영과 |
|---|---|---|
| JWT 서명 키 | `/lunchcatch/dev/jwt-signing-key` | **다르다.** 개발에서 찍은 토큰이 운영에서 통과하면 안 된다 |
| MySQL 비밀번호 | `/lunchcatch/dev/db-password` | 다르다. 컨테이너 안에서만 쓴다 |
| 카카오 네 값 | `/lunchcatch/kakao-*` | 같다. 같은 카카오 앱을 쓴다 |

개발 전용 둘은 `dev-up.sh` 가 없으면 만들어 넣는다. 사람이 정할 값이 아니다.

서버 역할은 `/lunchcatch/dev/*` 와 카카오 넷만 읽는다. 운영 DB 비밀번호나 운영 JWT 키는 읽지 못한다.

## 6. 배포

```
lc-backend develop 병합
  -> GitHub Actions (deploy-dev.yml)
     1. jar 빌드, 이미지를 개발 ECR 에 push (태그는 커밋 SHA)
     2. SSM /lunchcatch/dev/current-sha 갱신
     3. 개발 서버가 떠 있으면 SSM Run Command 로 새 이미지를 받아 재시작
     4. https://api.dev.lunchcatch.com/v3/api-docs 스모크
     개발 서버가 내려가 있으면 3, 4 를 건너뛴다. 다음에 올릴 때 2 의 SHA 로 뜬다
```

| 무엇 | 왜 |
|---|---|
| **개발 전용 배포 역할** `lunchcatch-gha-deploy-dev` | develop 브랜치에서만 맡을 수 있다. 개발 ECR push, 개발 SHA 갱신, 개발 서버 Run Command 만 한다. **운영 배포 역할을 develop 에 열지 않는다.** develop 에는 리뷰 전 코드가 들어간다 |
| **개발 ECR** `lunchcatch-dev` 를 `bootstrap/` 에 | 개발 서버가 내려가 있어도 develop 병합마다 이미지는 쌓여야 한다. 운영 ECR 은 운영 destroy 때 사라진다 |
| 롤링 없이 재시작 | 서버가 하나다. 몇십 초 끊겨도 된다 |

## 7. 올리고 내리기

| 명령 | 하는 일 | 내린 동안 비용 |
|---|---|---|
| `./scripts/dev-up.sh` | 없으면 만들고, 멈춰 있으면 켠 뒤 최신 develop(`dev/current-sha`)으로 맞춘다. 시크릿이 없으면 만든다 | |
| `./scripts/dev-down.sh` | **중지한다.** 지우지 않는다 | 디스크와 고정 IP. 월 약 5 USD |
| `terraform -chdir=dev destroy` | 지운다. 오래 안 쓸 때 | 0 (개발 ECR 이미지 보관료만) |

**내리기가 삭제가 아니라 중지인 이유는 인증서다.** 서버를 지웠다 만들면 Caddy 가 인증서를 새로 받는데, Let's Encrypt 는 같은 이름에 주 5회까지만 발급한다. 중지하면 디스크의 인증서와 MySQL 데이터가 남고, 켜는 데 1분 남짓이다. Caddy 는 Let's Encrypt 가 막히면 ZeroSSL 로 넘어가므로 삭제를 반복해도 서비스가 끊기지는 않지만, 기대지 않는다.

**데이터는 개발용이다.** 지우면 사라지고 Flyway 가 스키마를 다시 만든다. 지켜야 할 데이터를 개발 서버에 두지 않는다.

| admin | `admin.dev.lunchcatch.com` |

DNS 레코드는 운영 프론트와 같이 Vercel 이 알려 주는 값을 받아 `bootstrap/dns.tf` 에 넣는다.

## 10. 팀원이 로그와 DB 를 보는 법

2026-10-15 에 더했다. 회원 탈퇴 오류를 찾으려 했는데, 배포로 컨테이너가 바뀌어 그 전 로그가 이미 없었고 팀원은 DB 를 볼 수단이 없었다.

```
 로그  앱 컨테이너 -> CloudWatch Logs /lunchcatch/dev/app (30일)  <- 팀원: ./scripts/dev-logs.sh
 DB    MySQL 127.0.0.1:3306 (서버 안쪽만) <- SSM 포트 포워딩      <- 팀원: ./scripts/dev-db.sh -> localhost:13306
```

| 무엇 | 어디 |
|---|---|
| 로그 전송 | 앱 컨테이너의 `awslogs` 드라이버 (`dev/templates/compose.yaml.tftpl`). `docker logs` 도 그대로 된다 |
| 로그 그룹 | `/lunchcatch/dev/app`, 30일 보관 (`dev/main.tf`) |
| DB 포트 | MySQL 을 서버 안쪽 주소 `127.0.0.1:3306` 에만 연다. 보안 그룹은 그대로라 인터넷에는 열리지 않는다 |
| DB 계정 | `team`. 데이터 읽기와 쓰기(SELECT, INSERT, UPDATE, DELETE)만. 테이블 구조는 못 바꾼다. 비밀번호는 SSM `/lunchcatch/dev/team-db-password`, refresh 가 맞춘다 |
| 팀원 접근 | `bootstrap/dev_team.tf` 의 역할 `lunchcatch-dev-team`. 팀원은 Organization 의 자기 계정에서 역할 전환으로 넘어온다 (2026-10-20, #10) |

**팀원이 할 수 있는 것은 셋뿐이다.** 2026-10-15 팀원 키로, 2026-10-20 역할 정책 시뮬레이션으로 확인했다.

| 시도 | 결과 |
|---|---|
| 개발 로그 읽기 | 된다 |
| 팀 DB 비밀번호 읽기, 개발 서버 3306 포트 포워딩 | 된다 |
| 다른 비밀값(`/lunchcatch/dev/db-password`), S3, 서버 셸 접속 | 거부 |
| `team` 계정으로 CREATE TABLE | 거부 |

**팀원 준비 (한 번)**

키를 나눠 주지 않는다. 팀원은 자기 계정으로 로그인한 뒤 우리 계정(762794225116)의 역할로 넘어온다. 자격 증명은 최대 4시간짜리 임시다.

| | macOS | Windows (PowerShell) |
|---|---|---|
| AWS CLI | `brew install awscli` | `winget install -e --id Amazon.AWSCLI` |
| 플러그인 | `brew install --cask session-manager-plugin` | `winget install -e --id Amazon.SessionManagerPlugin` |
| 설정 파일 | `~/.aws/config` | `%UserProfile%\.aws\config` |
| 스크립트 실행 허용 | 필요 없음 | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` (한 번) |

1. 자기 계정에 **IAM 사용자**로 로그인할 수 있어야 한다. 루트 사용자(이메일 로그인)는 역할 전환을 못 한다. 그 사용자에게 `sts:AssumeRole` 권한이 있어야 하고 `AdministratorAccess` 면 이미 있다
2. 그 IAM 사용자의 액세스 키를 자기 프로필(예: `me`)로 넣는다. `aws configure --profile me`
3. `config` 에 아래를 더한다. `source_profile` 은 2번의 프로필 이름이다

```ini
[profile lunchcatch-dev]
role_arn = arn:aws:iam::762794225116:role/lunchcatch-dev-team
source_profile = me
region = ap-northeast-2
duration_seconds = 14400
```

4. `aws sts get-caller-identity --profile lunchcatch-dev` 가 `assumed-role/lunchcatch-dev-team/...` 을 보이면 된다
5. `git clone https://github.com/lunch-catch/lc-infra.git`. Windows 는 설치한 뒤 터미널을 새로 연다. 새 PATH 는 새 창에서만 잡힌다

**콘솔에서 로그 보기.** 자기 계정 콘솔에 IAM 사용자로 로그인한 뒤 아래 링크를 연다. 한 번 넘어오면 오른쪽 위 메뉴에 `lunchcatch-dev` 가 남는다. CloudWatch -> 로그 그룹 `/lunchcatch/dev/app` 에서 검색, Live Tail, Logs Insights 를 쓴다.

```
https://signin.aws.amazon.com/switchrole?account=762794225116&roleName=lunchcatch-dev-team&displayName=lunchcatch-dev
```

**쓰는 법**

```bash
# macOS
./scripts/dev-logs.sh                     # 최근 10분부터 실시간
./scripts/dev-logs.sh 2h ERROR            # 최근 2시간의 ERROR 만
./scripts/dev-db.sh                       # 열어 둔 동안 localhost:13306 으로 붙는다. 접속 정보를 출력한다
```

```powershell
# Windows (PowerShell)
.\scripts\dev-logs.ps1
.\scripts\dev-logs.ps1 2h ERROR
.\scripts\dev-db.ps1
```

Windows 판(`*.ps1`)은 macOS 판과 같은 일을 한다. 실행 정책 때문에 막히면 `powershell -ExecutionPolicy Bypass -File .\scripts\dev-db.ps1` 로 돌린다.

**팀원이 바뀌면** `bootstrap/terraform.tfvars` 의 `dev_team_accounts` 에 이름과 12자리 계정 ID 를 더하거나 빼고 apply 한다. 계정 ID 는 저장소가 PUBLIC 이라 커밋하지 않는 그 파일에만 둔다. 목록에 있어도 Organization(`o-2e7zqxkzzh`) 밖으로 옮긴 계정은 넘어오지 못한다.

처음에는 팀원마다 IAM 사용자(`lunchcatch-dev-<GitHub 아이디>`)와 액세스 키를 두었다. 역할 전환으로 바꾸면서 지운다.

**개발 서버를 새로 만들면** 템플릿에 들어 있어 그대로 이어진다. 개발 DB 는 비어서 시작한다.

## 11. 개발 Grafana

2026-10-21 에 더했다. 개발 서버의 지표와 로그를 운영과 같은 Grafana 화면으로 본다. 서버를 t3.medium(4 GB)으로 올려 Prometheus 와 Grafana 를 같은 서버에 띄운다.

```
 브라우저 https://grafana.dev.lunchcatch.com -> Caddy(인증서) -> Grafana
                                                     |- Prometheus (같은 서버, 앱 /actuator/prometheus 15초마다, 30일)
                                                     |- CloudWatch Logs /lunchcatch/dev/app (서버 역할로 읽기, 30일)
```

| 무엇 | 어디 |
|---|---|
| 컨테이너 | `dev/templates/compose.yaml.tftpl` 의 `prometheus`, `grafana` |
| 설정과 대시보드 | `dev/observability/`(Prometheus, 데이터 소스, 개발 로그 대시보드)와 운영의 `observability/grafana/dashboards`. refresh 가 서버의 `/opt/lunchcatch-dev/infra` 에 lc-infra main 을 받아 두고 읽는다. 병합하면 다음 refresh 에 들어간다 |
| 도메인 | `dev/main.tf` 의 `aws_route53_record.grafana`, Caddyfile |
| 로그 읽기 권한 | 서버 역할의 `GrafanaReadAppLogs`, `GrafanaListLogs` |

**로그인.** 인터넷에 열려 있어 가입과 익명 접근을 막았다. 계정은 둘이다.

| 계정 | 권한 | 비밀번호 |
|---|---|---|
| `team` | 보기 (Viewer) | SSM `/lunchcatch/dev/grafana-team-password`. 팀원이 개발 팀 역할로 직접 읽는다 |
| `admin` | 관리 | SSM `/lunchcatch/dev/grafana-admin-password`. 팀원은 못 읽는다 |

```bash
# 팀원이 비밀번호를 읽는다 (Windows 도 같다)
aws ssm get-parameter --name /lunchcatch/dev/grafana-team-password --with-decryption --query Parameter.Value --output text --profile lunchcatch-dev
```

두 비밀번호는 `dev-up.sh` 가 없을 때 만든다. refresh 가 매번 Grafana 의 관리자 비밀번호와 `team` 계정을 SSM 값으로 맞춘다. 관리자 비밀번호가 SSM 에 없으면 refresh 는 Grafana 를 띄우지 않는다. 기본값(`admin`)으로 인터넷에 열리지 않게 하려는 것이다. Grafana 는 로그인을 다섯 번 틀리면 그 계정을 잠시 막는다.

**대시보드.** 운영과 같은 01 ~ 06 에 개발 전용 07(개발 앱 로그)을 더했다. 개발에 없는 것(RDS, ALB, 배치 서버, 호스트 지표, Loki)을 보는 패널은 비어 보인다. 로그는 07 이나 Explore 에서 CloudWatch 를 골라 Logs Insights 쿼리로 본다.

**비밀번호를 바꾸려면** SSM 값을 바꾸고 `sudo /usr/local/bin/lunchcatch-dev-refresh` 를 돌린다.
