# 팀원 부하 시험 환경

백엔드 팀원이 자기 AWS 계정에 운영과 같은 인프라를 한 벌 띄워 각자 부하 시험을 한다 (lc-infra #11, 2026-10-20).

2026-10-31 에 AWS 조직을 해제하면서 다른 계정에 기대는 것을 모두 걷어냈다 (lc-infra #52). 필요한 것은 자기 계정 하나다.

**준비, 쓰는 법, 막혔을 때는 위키에 있다** (`docs/wiki/팀원-부하시험-환경.md`). 여기에는 설계와 이유만 둔다.

```
 팀원 A 계정   k6 -> ALB -> 앱 2대 -> RDS, Valkey   (+ 배치 2대, 모니터링)
 팀원 B 계정   k6 -> ALB -> 앱 2대 -> RDS, Valkey   (+ 배치 2대, 모니터링)
 ...
 GitHub        GHCR 공개 패키지(ghcr.io/lunch-catch/lc-backend) <- 서버를 띄울 때 이미지를 로그인 없이 받아 간다
```

## 1. 무엇이 같고 무엇이 다른가

운영과 같은 모듈(`modules/`)을 부하 시험 루트(`envs/lt/`)로 부른다. 아래 차이는 그 루트가 값으로 갖는다. `scripts/member-env.sh` 는 계정마다 상태 버킷과 변수 파일과 `.terraform` 을 `~/.lunchcatch-member/<계정 ID>-lt/` 아래에 두고 그 루트를 그대로 돌린다.

| 항목 | 운영 | 팀원 한 벌 | 부하 시험에 주는 영향 |
|---|---|---|---|
| 서버 크기와 대수 | 앱 t3.small 2~3대, 배치 2대, 모니터링 | 같다 | 없다 |
| DB, 캐시 | RDS MySQL (다중 AZ), ElastiCache Valkey | 같은 등급, 빈 DB | 시험 데이터는 시드나 스냅샷으로 넣는다 |
| 부하 생성기 | `loadtest-box.sh` 로 켤 때만 | 항상 켠다 (m7i-flex.large) | 없다 |
| 도메인과 HTTPS | `api.lunchcatch.com`, HTTPS | 없다. ALB 주소로 HTTP | TLS 처리 부하가 빠진다 |
| 앱 이미지 | 운영 ECR, lc-backend `main` | GHCR 공개 패키지, lc-backend `develop` (`app_image_repository`) | 운영보다 앞선 코드로 시험한다. `--sha` 로 바꾼다 |
| 삭제 보호, 최종 스냅샷 | RDS, ALB, 모니터링에 삭제 보호를 걸고 RDS 를 지울 때 최종 스냅샷을 남긴다 | `envs/lt` 가 `deletion_protection = false` 로 둘 다 끈다. `down` 과 자동 정리가 막힘 없이 지우게 한다 | 없다 |
| 운영 모드 | `apply.sh` 기본 `loadtest`, 실결제는 `--mode live` | 항상 `loadtest` | 결제는 토스 대신 목이 받고 지연 200ms 를 흉내 낸다 |
| 시크릿 | 실제 값 | JWT 키와 DB 비밀번호는 무작위, 카카오와 Slack 은 더미 | 카카오 로그인은 시나리오에서 빼거나 가짜 응답으로 바꾼다 |
| 시험 시간 | 제한 없음 | 제한 없음. 끝나면 `down`. `MEMBER_HOURS` 를 주면 그 시간 뒤 AWS 가 스스로 지운다 (2절) | 없다 |
| 예산 알림 | 운영 설정 | 월 50 USD | 없다 |
| 이미지 저장소와 CDN | `cdn.lunchcatch.com` | 계정별 버킷(`lunchcatch-lt-media-<계정 ID>`), CloudFront 기본 주소 | 없다 |

**결과를 읽을 때 다른 점.** 앱, DB, 캐시가 받는 부하는 운영과 같은 조건이다. 다만 세 가지가 다르다. HTTP 로 ALB 를 직접 쳐서 TLS 처리 부하가 빠진다. 결제는 목이 받고 카카오는 시나리오에서 빠져 외부 호출 지연이 실제와 다르다. 코드는 기본으로 `develop` 이다.

**ECR 이 아니라 GHCR 공개 패키지를 쓰는 이유.** ECR 은 그 계정 것이라 다른 계정이 받으려면 저장소 정책으로 열어 줘야 한다. 전에는 개발 ECR 을 조직 계정에만 열었는데, 조직을 해제하면서 그 길이 없어졌다. 공개 패키지는 로그인 없이 받으므로 어느 계정에서도 같다. 이미지에는 공개 저장소의 jar 만 들어가고 시크릿은 실행 시점에 SSM 에서 받으므로 공개해도 새로 드러나는 것이 없다. 이미지가 ECR 이 아니면 compute 모듈이 ECR 로그인과 pull 권한을 만들지 않는다.

**이미지는 `develop` 기준이다.** lc-backend 의 이미지 공개 워크플로(`image.yml`, 원본은 `docs/deploy/backend-image-workflow.yml`)가 `develop` 커밋마다 `ghcr.io/lunch-catch/lc-backend:<SHA>` 를 올린다. `up` 은 그 워크플로가 `develop` 에서 마지막으로 성공한 커밋으로 띄운다. 운영(`main`)과 같은 버전으로 시험하려면 `up --sha <커밋>` 을 준다. 그 커밋의 이미지가 GHCR 에 있어야 하므로, `develop` 을 거친 커밋이어야 한다. `up` 은 띄우기 전에 태그가 있는지 본다.

**서로 영향을 받지 않는다.** 부하가 지나가는 길(k6, ALB, 앱, DB, 캐시)이 전부 자기 계정 안에 있다. vCPU, IP, API 호출 한도도 계정 단위다. 밖에서 받는 것은 서버가 뜰 때의 이미지뿐이다.

**결제는 목이다.** 팀원 한 벌은 항상 `loadtest` 프로필로 뜬다. 이 프로필에서는 토스를 부르지 않고 앱 안의 목(`LoadTestPaymentGateway`, lc-backend #715)이 승인을 돌려준다. 승인 지연은 기본 200ms 다. `up` 이 SSM `/lunchcatch-lt/run-mode` 를 `loadtest` 로 적고, `up` 과 `status` 가 `운영 모드` 줄로 보여 준다. 운영 모드는 배포 문서(docs/deploy/README.md)에 있다.

**카카오는 같이 쓴다.** 키가 같으면 그쪽 요청 한도를 나눠 쓴다. 부하 시험 시나리오에서 빼거나 가짜 응답으로 바꾼다.

**운영 코드가 바뀌면.** `git pull` 하고 `up` 을 다시 부르면 바뀐 부분만 반영된다. 스크립트는 로컬 코드가 `origin/main` 과 다르면 멈춘다.

## 2. 자동 정리 (선택)

기본은 꺼져 있다 (#52). 각자 자기 계정으로 돌리므로 시험 시간을 막지 않는다. 처음에는 공용 청구 계정의 비용을 막으려고 4시간 뒤 무조건 지웠다. 이제 비용은 띄운 사람의 계정으로 가고, 언제 지울지도 그 사람이 정한다. `MEMBER_HOURS=<시간>` 을 주면 아래 일정이 생긴다.

`envs/lt/cleanup.tf` 가 EventBridge Scheduler 로 정리 시각에 AWS API 를 직접 부른다. 노트북을 닫아도 돈다.

| 정리 시각에 | 대상 |
|---|---|
| 0분 | 앱과 배치 ASG 를 0대로, 모니터링과 부하 생성기 종료, NAT 삭제, ALB 삭제, 캐시 삭제, RDS 삭제(스냅샷 없음) |
| 30분 | NAT 고정 IP 반납 |

남는 것은 VPC, 보안 그룹, S3, CloudFront, SSM 이다. 거의 돈이 들지 않는다. 다음 `down` 이 지운다.

`MEMBER_HOURS` 를 주고 `up` 을 다시 부르면 정리 시각이 지금부터 다시 세어진다. 주지 않고 부르면 일정이 지워진다. 정리된 뒤 `up` 을 부르면 지워진 것을 다시 만든다.

## 3. 비용

| | 시간당 | 4시간 시험 | 하루 켜 둠 | 한 달 켜 둠 |
|---|---|---|---|---|
| 1벌 | 약 0.4~0.6 USD | 약 2 USD | 약 10~15 USD | 약 300~430 USD |

청구는 띄운 사람의 계정으로 간다. **기본으로 자동 정리가 없어서 `down` 을 잊으면 계속 나간다.** 잊을 것 같으면 `MEMBER_HOURS` 를 주거나 `MEMBER_ALERT_EMAIL` 로 예산 알림(월 50 USD)을 받는다.

## 4. 같은 계정에 운영이 있을 때

접두사는 어느 계정에서나 `lunchcatch-lt` 다. 리소스 이름, SSM 경로(`/lunchcatch-lt/*`), 상태 버킷(`tfstate-lunchcatch-lt-<계정 ID>`), 작업 디렉터리(`~/.lunchcatch-member/<계정 ID>-lt/`)가 운영(`lunchcatch`)과 갈린다. 그래서 운영을 올리는 계정에서도 이름이 부딪히지 않는다.

**운영과 함께 띄우지 않는다.** 두 쪽이 서로를 막는다.

| 먼저 떠 있는 것 | 막히는 것 | 이유 |
|---|---|---|
| 운영 (DB 나 서버가 남아 있다) | `member-env.sh up` | 계정 vCPU 한도를 나눠 쓴다. Prometheus 와 CloudWatch 익스포터가 계정의 서버와 ALB, RDS 를 모두 찾아 두 쪽 지표가 섞이고, 운영 경보가 시험 부하로 울린다 |
| `lunchcatch-lt` 서버 | `apply.sh`, `start.sh` | 같은 이유다 |

개발 서버(`Role=dev-server`)는 세지 않는다. 함께 떠 있어도 된다.

**예산 알림.** AWS 예산은 계정 전체를 센다. 계정에 다른 것이 함께 돌면 시험 비용과 섞이므로 그때는 `MEMBER_ALERT_EMAIL` 을 주지 않는다.

**Bedrock.** 모델 사용 신청을 한 계정에서만 템플릿 생성 API 가 돈다. 부하 시험 대상은 아니다.
