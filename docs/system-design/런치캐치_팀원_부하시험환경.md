# 팀원 부하 시험 환경

백엔드 팀원이 Organization 의 자기 AWS 계정에 운영과 같은 인프라를 한 벌 띄워 각자 부하 시험을 한다 (lc-infra #11, 2026-10-20).

```
 팀원 A 계정   k6 -> ALB -> 앱 2대 -> RDS, Valkey   (+ 배치 2대, 모니터링)
 팀원 B 계정   k6 -> ALB -> 앱 2대 -> RDS, Valkey   (+ 배치 2대, 모니터링)
 ...
 우리 계정     개발 ECR(lunchcatch-dev) <- 위 계정들이 서버를 띄울 때 이미지를 한 번 받아 간다
```

## 1. 무엇이 같고 무엇이 다른가

같은 Terraform 코드(`terraform/`)를 그대로 쓴다. `scripts/member-env.sh` 가 매번 운영 코드를 작업 사본(`~/.lunchcatch-member/<계정 ID>/`)에 복사하고 아래 차이만 얹는다.

| 항목 | 운영 | 팀원 한 벌 |
|---|---|---|
| 서버 크기와 대수 | 앱 t3.small 2~3대, 배치 2대, 모니터링 | 같다 |
| DB, 캐시 | RDS MySQL (다중 AZ), ElastiCache Valkey | 같은 등급, 빈 DB |
| 부하 생성기 | `loadtest-box.sh` 로 켤 때만 | 항상 켠다 (m7i-flex.large) |
| 도메인과 HTTPS | `api.lunchcatch.com` | 없다. ALB 주소로 HTTP |
| 앱 이미지 | 운영 ECR | 우리 계정의 개발 ECR (`app_image_repository`) |
| 삭제 보호 | RDS, ALB, 모니터링에 건다 | 사본에서 끈다 |
| 운영 모드 | `apply.sh` 기본 `loadtest`, 실결제는 `--mode live` | 항상 `loadtest` |
| 시크릿 | 실제 값 | JWT 키와 DB 비밀번호는 무작위, 카카오와 Slack 은 더미 |
| 자동 정리 | 없다 | 4시간 뒤 AWS 가 스스로 지운다 (4절) |

**운영 ECR 이 아니라 개발 ECR 을 쓰는 이유.** 운영 ECR 은 `terraform/` 이 갖고 있어 운영을 내리면 이미지와 함께 지워진다. 개발 ECR 은 `bootstrap/` 에 있어 남는다. `bootstrap/dev.tf` 가 Organization 계정에만 받기를 연다.

**서로 영향을 받지 않는다.** 부하가 지나가는 길(k6, ALB, 앱, DB, 캐시)이 전부 자기 계정 안에 있다. vCPU, IP, API 호출 한도도 계정 단위다. 같이 쓰는 것은 개발 ECR 뿐이고 서버가 뜰 때 이미지를 받아 갈 뿐이다.

**결제는 목이다.** 팀원 한 벌은 항상 `loadtest` 프로필로 뜬다. 이 프로필에서는 토스를 부르지 않고 앱 안의 목(`LoadTestPaymentGateway`, lc-backend #715)이 승인을 돌려준다. 승인 지연은 기본 200ms 다. `up` 이 SSM `/lunchcatch/run-mode` 를 `loadtest` 로 적고, `up` 과 `status` 가 `운영 모드` 줄로 보여 준다. 운영 모드는 배포 문서(docs/deploy/README.md)에 있다.

**카카오는 같이 쓴다.** 키가 같으면 그쪽 요청 한도를 나눠 쓴다. 부하 시험 시나리오에서 빼거나 가짜 응답으로 바꾼다.

**운영 코드가 바뀌면.** `git pull` 하고 `up` 을 다시 부르면 바뀐 부분만 반영된다. 스크립트는 로컬 코드가 `origin/main` 과 다르면 멈춘다.

## 2. 준비 (한 번)

| 필요한 것 | 확인 |
|---|---|
| 자기 계정의 관리자 IAM 사용자 | `AdministratorAccess`. 루트 키는 쓰지 않는다 |
| 그 사용자의 CLI 프로필 | `aws configure --profile me` |
| AWS CLI | `aws --version` |
| Terraform 1.15 | `terraform version`. `brew install hashicorp/tap/terraform` |
| git, openssl, bash | macOS 와 Linux 는 기본으로 있다. **Windows 는 WSL 에서 돌린다** |
| Session Manager 플러그인 | 부하 생성기와 Grafana 에 붙을 때. `brew install --cask session-manager-plugin` |
| EC2 vCPU 한도 14 이상 | 아래 명령. 낮으면 Service Quotas 에서 증가를 요청한다 (하루쯤 걸린다) |

```
aws service-quotas get-service-quota --service-code ec2 --quota-code L-1216C47A --query Quota.Value --profile me
```

## 3. 쓰는 법

lc-infra 를 최신으로 받은 뒤 그 폴더에서 돌린다.

```bash
git pull
AWS_PROFILE=me ./scripts/member-env.sh up       # 처음은 20분쯤. 끝나면 ALB 주소와 정리 시각을 보여 준다
AWS_PROFILE=me ./scripts/member-env.sh status   # 떠 있는 것, 정리 시각, Grafana 접속 방법
AWS_PROFILE=me ./scripts/member-env.sh down     # 다 끝나면 지운다
```

| 옵션 | 뜻 |
|---|---|
| `up --sha <커밋>` | 개발 ECR 의 그 커밋 이미지로 띄운다. 없으면 가장 최근 이미지 |
| `MEMBER_ALERT_EMAIL=<메일>` | 예산 알림(월 50 USD 기준)과 경보를 메일로 받는다. 처음 오는 확인 메일의 링크를 누른다 |
| `MEMBER_HOURS=<시간>` | 자동 정리까지의 시간. 기본 4 |

**부하 생성기.** `up` 이 보여 주는 `aws ssm start-session --target i-...` 로 붙는다. 시나리오와 토큰 발급은 lc-backend 의 `loadtest/` 를 따른다 (부팅 때 받아 둔다). 대상 주소는 `/opt/loadtest/env` 에 들어 있다.

**Grafana.** `status` 가 보여 주는 포트 포워딩 명령을 연 동안 `http://localhost:13000`. 사용자 `admin`, 비밀번호는 SSM `/lunchcatch/grafana-admin-password`. 운영과 같은 대시보드(06 광고 서빙 포함)가 들어 있다.

**데이터.** DB 는 비어서 시작한다. 시험 데이터는 lc-backend 의 부하 시험 준비 절차로 넣는다.

## 4. 자동 정리

`member/cleanup.tf` 가 EventBridge Scheduler 로 정리 시각에 AWS API 를 직접 부른다. 노트북을 닫아도 돈다.

| 정리 시각에 | 대상 |
|---|---|
| 0분 | 앱과 배치 ASG 를 0대로, 모니터링과 부하 생성기 종료, NAT 삭제, ALB 삭제, 캐시 삭제, RDS 삭제(스냅샷 없음) |
| 30분 | NAT 고정 IP 반납 |

남는 것은 VPC, 보안 그룹, S3, CloudFront, SSM 이다. 거의 돈이 들지 않는다. 다음 `down` 이 지운다.

`up` 을 다시 부르면 정리 시각이 지금부터 다시 4시간으로 밀린다. 정리된 뒤 `up` 을 부르면 지워진 것을 다시 만든다.

## 5. 비용

| | 시간당 | 4시간 시험 |
|---|---|---|
| 1벌 | 약 0.4~0.6 USD | 약 2 USD |
| 5벌 동시 | 약 2~3 USD | 약 8~12 USD |

청구는 Organization 관리 계정으로 모인다. 자동 정리 덕에 잊어도 4시간치 이상은 거의 나가지 않는다.

| 앱이 10분 안에 응답하지 않는다 | 모니터링(Grafana, Loki)이나 `aws ssm start-session` 으로 앱 서버의 `docker logs lunchcatch` 를 본다 |
