# 팀원 부하 시험 환경

백엔드 팀원이 Organization 의 자기 AWS 계정에 운영과 같은 인프라를 한 벌 띄워 각자 부하 시험을 한다 (lc-infra #11, 2026-10-20).

**준비, 쓰는 법, 막혔을 때는 위키에 있다** (`docs/wiki/팀원-부하시험-환경.md`). 여기에는 설계와 이유만 둔다.

```
 팀원 A 계정   k6 -> ALB -> 앱 2대 -> RDS, Valkey   (+ 배치 2대, 모니터링)
 팀원 B 계정   k6 -> ALB -> 앱 2대 -> RDS, Valkey   (+ 배치 2대, 모니터링)
 ...
 우리 계정     개발 ECR(lunchcatch-dev) <- 위 계정들이 서버를 띄울 때 이미지를 한 번 받아 간다
```

## 1. 무엇이 같고 무엇이 다른가

운영과 같은 모듈(`modules/`)을 부하 시험 루트(`envs/lt/`)로 부른다. 아래 차이는 그 루트가 값으로 갖는다. `scripts/member-env.sh` 는 계정마다 상태 버킷과 변수 파일과 `.terraform` 을 `~/.lunchcatch-member/<계정 ID>/` 아래에 두고 그 루트를 그대로 돌린다.

| 항목 | 운영 | 팀원 한 벌 | 부하 시험에 주는 영향 |
|---|---|---|---|
| 서버 크기와 대수 | 앱 t3.small 2~3대, 배치 2대, 모니터링 | 같다 | 없다 |
| DB, 캐시 | RDS MySQL (다중 AZ), ElastiCache Valkey | 같은 등급, 빈 DB | 시험 데이터는 시드나 스냅샷으로 넣는다 |
| 부하 생성기 | `loadtest-box.sh` 로 켤 때만 | 항상 켠다 (m7i-flex.large) | 없다 |
| 도메인과 HTTPS | `api.lunchcatch.com`, HTTPS | 없다. ALB 주소로 HTTP | TLS 처리 부하가 빠진다 |
| 앱 이미지 | 운영 ECR, lc-backend `main` | 우리 계정의 개발 ECR, lc-backend `develop` (`app_image_repository`) | 운영보다 앞선 코드로 시험한다. `--sha` 로 바꾼다 |
| 삭제 보호, 최종 스냅샷 | RDS, ALB, 모니터링에 삭제 보호를 걸고 RDS 를 지울 때 최종 스냅샷을 남긴다 | `envs/lt` 가 `deletion_protection = false` 로 둘 다 끈다. `down` 과 자동 정리가 막힘 없이 지우게 한다 | 없다 |
| 운영 모드 | `apply.sh` 기본 `loadtest`, 실결제는 `--mode live` | 항상 `loadtest` | 결제는 토스 대신 목이 받고 지연 200ms 를 흉내 낸다 |
| 시크릿 | 실제 값 | JWT 키와 DB 비밀번호는 무작위, 카카오와 Slack 은 더미 | 카카오 로그인은 시나리오에서 빼거나 가짜 응답으로 바꾼다 |
| 자동 정리 | 없다 | 4시간 뒤 AWS 가 스스로 지운다 (2절) | 없다 |
| 예산 알림 | 운영 설정 | 월 50 USD | 없다 |
| 이미지 저장소와 CDN | `cdn.lunchcatch.com` | 계정별 버킷(`lunchcatch-media-<계정 ID>`), CloudFront 기본 주소 | 없다 |

**결과를 읽을 때 다른 점.** 앱, DB, 캐시가 받는 부하는 운영과 같은 조건이다. 다만 세 가지가 다르다. HTTP 로 ALB 를 직접 쳐서 TLS 처리 부하가 빠진다. 결제는 목이 받고 카카오는 시나리오에서 빠져 외부 호출 지연이 실제와 다르다. 코드는 기본으로 `develop` 이다.

**운영 ECR 이 아니라 개발 ECR 을 쓰는 이유.** 운영 ECR 은 `envs/prod/` 이 갖고 있어 운영을 내리면 이미지와 함께 지워진다. 개발 ECR 은 `bootstrap/` 에 있어 남는다. `bootstrap/dev.tf` 가 Organization 계정에만 받기를 연다.

**이미지는 `develop` 기준이다.** `up` 은 개발 ECR 에 가장 최근에 올라온 이미지로 띄운다. 그 이미지는 lc-backend 의 `deploy-dev.yml` 이 `develop` 병합 때 올린다. 그래서 기본으로는 운영(`main`)보다 앞선 코드로 시험한다. 운영과 같은 버전으로 시험하려면 `up --sha <main 커밋>` 을 준다. 그 커밋 이미지가 개발 ECR 에도 있어야 한다. 누가 `deploy-dev.yml` 을 다른 브랜치로 손으로 돌리면 그 이미지가 가장 최근 것이 되므로 `up` 이 보여 주는 커밋을 확인한다.

**서로 영향을 받지 않는다.** 부하가 지나가는 길(k6, ALB, 앱, DB, 캐시)이 전부 자기 계정 안에 있다. vCPU, IP, API 호출 한도도 계정 단위다. 같이 쓰는 것은 개발 ECR 뿐이고 서버가 뜰 때 이미지를 받아 갈 뿐이다.

**결제는 목이다.** 팀원 한 벌은 항상 `loadtest` 프로필로 뜬다. 이 프로필에서는 토스를 부르지 않고 앱 안의 목(`LoadTestPaymentGateway`, lc-backend #715)이 승인을 돌려준다. 승인 지연은 기본 200ms 다. `up` 이 SSM `/lunchcatch/run-mode` 를 `loadtest` 로 적고, `up` 과 `status` 가 `운영 모드` 줄로 보여 준다. 운영 모드는 배포 문서(docs/deploy/README.md)에 있다.

**카카오는 같이 쓴다.** 키가 같으면 그쪽 요청 한도를 나눠 쓴다. 부하 시험 시나리오에서 빼거나 가짜 응답으로 바꾼다.

**운영 코드가 바뀌면.** `git pull` 하고 `up` 을 다시 부르면 바뀐 부분만 반영된다. 스크립트는 로컬 코드가 `origin/main` 과 다르면 멈춘다.

## 2. 자동 정리

`envs/lt/cleanup.tf` 가 EventBridge Scheduler 로 정리 시각에 AWS API 를 직접 부른다. 노트북을 닫아도 돈다.

| 정리 시각에 | 대상 |
|---|---|
| 0분 | 앱과 배치 ASG 를 0대로, 모니터링과 부하 생성기 종료, NAT 삭제, ALB 삭제, 캐시 삭제, RDS 삭제(스냅샷 없음) |
| 30분 | NAT 고정 IP 반납 |

남는 것은 VPC, 보안 그룹, S3, CloudFront, SSM 이다. 거의 돈이 들지 않는다. 다음 `down` 이 지운다.

`up` 을 다시 부르면 정리 시각이 지금부터 다시 4시간으로 밀린다. 정리된 뒤 `up` 을 부르면 지워진 것을 다시 만든다.

## 3. 비용

| | 시간당 | 4시간 시험 |
|---|---|---|
| 1벌 | 약 0.4~0.6 USD | 약 2 USD |
| 5벌 동시 | 약 2~3 USD | 약 8~12 USD |

청구는 Organization 관리 계정으로 모인다. 자동 정리 덕에 잊어도 4시간치 이상은 거의 나가지 않는다.

## 4. 우리 계정에서 띄우기

조직에 따로 멤버 계정이 없는 사람(운영 담당)이 같은 환경으로 시험할 때 쓴다 (2026-10-22). 명령은 팀원과 같고 프로필만 `lunchcatch` 다 (위키 6절).

**접두사가 바뀐다.** 계정이 762794225116 이면 `member-env.sh` 가 접두사를 `lunchcatch-lt` 로 바꾼다. 리소스 이름, SSM 경로(`/lunchcatch-lt/*`), 상태 버킷(`tfstate-lunchcatch-lt-762794225116`), 작업 디렉터리(`~/.lunchcatch-member/762794225116-lt/`)가 모두 운영과 갈린다. 이미지는 같은 개발 ECR(`lunchcatch-dev`)에서 받는다.

**운영과 함께 띄우지 않는다.** 두 쪽이 서로를 막는다.

| 먼저 떠 있는 것 | 막히는 것 | 이유 |
|---|---|---|
| 운영 (DB 나 서버가 남아 있다) | `member-env.sh up` | 계정 vCPU 한도(32)를 나눠 쓴다. Prometheus 와 CloudWatch 익스포터가 계정의 서버와 ALB, RDS 를 모두 찾아 두 쪽 지표가 섞이고, 운영 경보가 시험 부하로 울린다 |
| `lunchcatch-lt` 서버 | `apply.sh`, `start.sh` | 같은 이유다 |

개발 서버(`Role=dev-server`)는 세지 않는다. 함께 떠 있어도 된다.

**팀원 환경과 다른 점.**

| 항목 | 팀원 계정 | 우리 계정 한 벌 |
|---|---|---|
| 계정 한도 | 혼자 쓴다 | 개발 서버와 나눠 쓴다. 운영과는 동시에 뜨지 않는다 |
| 예산 알림 (월 50 USD) | 그 한 벌의 비용 | AWS 예산은 계정 전체를 세서 개발 서버 비용이 섞인다. 맞지 않으므로 `MEMBER_ALERT_EMAIL` 을 주지 않는다 |
| Bedrock | 모델 사용 신청을 안 해 못 쓴다 | 우리 계정은 승인돼 있어 쓴다 (부하 시험 대상은 아니다) |

부하가 지나가는 길(k6, ALB, 앱, DB, 캐시)과 서버 크기는 팀원 환경과 같아 결과를 서로 비교할 수 있다.
