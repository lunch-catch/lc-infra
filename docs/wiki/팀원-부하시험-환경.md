# 팀원 부하 시험 환경

백엔드 팀원이 자기 AWS 계정에 운영과 같은 인프라를 한 벌 띄워 각자 부하 시험을 한다 (lc-infra #11, #52). 필요한 것은 자기 계정 하나다. 계정이 나뉘어 서로의 시험이 영향을 주지 않는다.

```
 팀원 A 계정   k6 -> ALB -> 앱 2대 -> RDS, Valkey   (+ 배치 2대, 모니터링)
 팀원 B 계정   k6 -> ALB -> 앱 2대 -> RDS, Valkey   (+ 배치 2대, 모니터링)
 GitHub        GHCR 공개 패키지(ghcr.io/lunch-catch/lc-backend) <- 서버를 띄울 때 이미지를 로그인 없이 받아 간다
```

설계와 이유(운영과 무엇이 다른가, 선택적 자동 정리)는 `docs/system-design/런치캐치_팀원_부하시험환경.md` 에 있다.

시험과 모니터링까지 처음부터 끝까지의 순서는 [팀원 부하 시험 가이드](./팀원-부하시험-가이드.md)가 갖는다. 이 문서는 환경을 띄우고 내리는 일을 갖는다.

## 1. 알아 둘 것

| 항목 | 내용 |
|---|---|
| 인프라 | 운영과 같은 Terraform 코드, 같은 서버 크기와 대수 |
| 앱 이미지 | lc-backend `develop` 에서 마지막으로 이미지를 올린 커밋. 다른 커밋은 `up --sha <커밋>` |
| 운영 모드 | 항상 `loadtest`. 결제는 토스 대신 앱 안의 목이 받고 지연 200ms 를 흉내 낸다 |
| 주소 | 도메인 없이 ALB 주소로 HTTP. TLS 처리 부하는 빠진다 |
| 데이터 | 빈 DB 로 시작한다 |
| 카카오 | 더미 값이다. 로그인은 시험용 토큰으로 대신한다 |
| 로그인 시도 제한 | IP 당 1분 10회. k6 한 대에서 로그인과 재발급을 돌리면 429 가 난다 |
| Bedrock | 쓰지 못한다. 템플릿 생성 API 는 시험에서 뺀다 |
| 시험 시간 | 제한 없다. 끝나면 `down` 으로 지운다. 켜 둔 동안 시간당 요금이 나간다(4절) |

## 2. 준비 (한 번)

| 필요한 것 | 확인 |
|---|---|
| 자기 AWS 계정 | 비용이 이 계정으로 나간다 |
| 그 계정의 관리자 IAM 사용자 | `AdministratorAccess`. 루트 키는 쓰지 않는다. 만드는 법은 아래 |
| 그 사용자의 CLI 프로필 | `aws configure --profile me`. 이름은 아무거나 되고, 아래 명령의 `me` 자리에 그 이름을 쓴다 |
| AWS CLI | `aws --version` |
| Terraform 1.15 | `terraform version`. `brew install hashicorp/tap/terraform` |
| git, curl, openssl, bash, python3 | macOS 와 Linux 는 기본으로 있다. python3 는 lc-backend 의 `run.sh` 가 원격 명령을 만들 때 쓴다. **Windows 는 WSL 에서 돌린다** |
| Session Manager 플러그인 | 부하 생성기와 Grafana 에 붙을 때. `brew install --cask session-manager-plugin` |
| EC2 vCPU 한도 14 이상 | 아래 명령. 낮으면 Service Quotas 에서 증가를 요청한다 (하루쯤 걸린다) |

```
aws service-quotas get-service-quota --service-code ec2 --quota-code L-1216C47A --query Quota.Value --profile me
```

**관리자 IAM 사용자와 프로필 만들기.** 이 환경은 VPC, RDS, IAM 역할까지 만들어서 관리자 권한이 필요하다.

1. 콘솔에 루트로 로그인해 IAM 으로 간다
2. 사용자를 만든다 (예: `lunchcatch-lt`). 권한은 "직접 정책 연결" 에서 `AdministratorAccess`
3. 그 사용자의 "보안 자격 증명" 에서 액세스 키를 만든다 (용도는 CLI)
4. `aws configure --profile me` 로 키를 넣는다. 리전은 `ap-northeast-2`
5. `aws sts get-caller-identity --profile me` 가 자기 계정 ID 를 보여 주면 된다

액세스 키는 `~/.aws/credentials` 에만 둔다. 저장소나 채팅에 붙이지 않는다. 오래 안 쓰면 키를 비활성화한다.

## 3. 쓰는 법

lc-infra 를 최신으로 받은 뒤 그 폴더에서 돌린다. `AWS_PROFILE` 은 꼭 준다. 엉뚱한 계정에 띄우지 않게 없으면 멈춘다.

```bash
git pull
AWS_PROFILE=me ./scripts/member-env.sh up       # 처음은 25분쯤. 앱과 모니터링이 준비되면 ALB 주소와 정리 시각을 보여 준다
AWS_PROFILE=me ./scripts/member-env.sh status   # 떠 있는 것, 정리 시각, 운영 모드, Grafana 접속 방법
AWS_PROFILE=me ./scripts/member-env.sh down     # 다 끝나면 지운다
```

| 옵션 | 뜻 |
|---|---|
| `up --sha <커밋>` | 그 커밋의 이미지로 띄운다. 짧은 SHA 도 된다. 없으면 `develop` 의 마지막 이미지 |
| `MEMBER_ALERT_EMAIL=<메일>` | 예산 알림(월 50 USD 기준)과 경보를 메일로 받는다. 처음 오는 확인 메일의 링크를 누른다 |
| `MEMBER_HOURS=<시간>` | 그 시간 뒤 AWS 가 서버, DB, 캐시, ALB, NAT 를 스스로 지운다. 노트북을 닫아도 돈다. 기본은 자동 정리 없음 |
| `MEMBER_SLACK_WEBHOOK_CRITICAL=<주소>`, `MEMBER_SLACK_WEBHOOK_WARNING=<주소>` | Prometheus 경보를 팀 Slack 채널로 받는다. 주소는 저장소에 없고 인프라 담당에게 따로 받는다. 안 주면 경보가 아무 데도 가지 않는다 |
| `MEMBER_NAME=<이름>` | 경보 제목 끝에 `(lunchcatch-lt/<이름>)` 으로 붙는다. 기본은 `git config user.name` |

**Slack 경보.** 웹훅 주소 두 개(critical, warning)는 인프라 담당에게 DM 으로 받는다. 받은 주소를 `~/.lunchcatch-member/slack.env` 에 아래처럼 적고 `chmod 600` 한다. 주소는 비밀값이라 셸 기록이나 저장소, 공개 채널에 남기지 않는다. 경보 제목 끝에 `(lunchcatch-lt/<이름>)` 이 붙어 누구 환경인지 구분된다.

```bash
export MEMBER_SLACK_WEBHOOK_CRITICAL='<받은 critical 주소>'
export MEMBER_SLACK_WEBHOOK_WARNING='<받은 warning 주소>'
```

```bash
source ~/.lunchcatch-member/slack.env && AWS_PROFILE=me ./scripts/member-env.sh up
```

- 주소는 **처음 `up` 할 때** 준다. 모니터링 서버가 부팅할 때 한 번 읽기 때문이다. 이미 떠 있으면 `down` 하고 다시 `up` 한다
- 한 번 넣으면 자기 계정 SSM 에 남아 다음 `up` 부터는 `source` 없이도 간다
- watchdog 은 주지 않는다. 경보 경로가 살아 있다는 신호라 환경마다 5분에 한 번씩 와서, 팀원 모두가 보내면 채널이 그것으로 찬다

`up` 은 앱이 응답하고 모니터링의 Prometheus 와 Grafana 가 준비될 때까지 기다린다. 끝나면 바로 시험해도 첫 회차부터 지표가 남는다.

`up` 을 다시 부르면 바뀐 코드만 반영한다. 다만 이미 떠 있는 모니터링 서버의 관측 설정(대시보드, 경보 규칙)은 바뀌지 않는다. 모니터링 서버는 처음 뜰 때만 lc-infra 를 받기 때문이다. 바뀐 대시보드를 보려면 `down` 한 뒤 `up` 하거나, 모니터링 서버에서 `git pull` 하고 Grafana 를 다시 띄운다(`docker restart grafana`). 경보 규칙(`prometheus/rules.yml`)도 바뀌었으면 Prometheus 도 다시 띄운다(`docker restart prometheus`). 환경을 내리지 않고 바꿀 수 있다. `MEMBER_HOURS` 를 주면 정리 시각을 지금부터 다시 세고, 안 주면 자동 정리를 없앤다. 정리된 뒤 `up` 을 부르면 지워진 것을 다시 만든다.

**부하 생성기.** `up` 이 보여 주는 `aws ssm start-session --target i-...` 로 붙는다. 시나리오와 토큰 발급은 lc-backend 의 `loadtest/` 를 따른다. 대상 주소는 `/opt/loadtest/env` 에 들어 있다.

시나리오는 부팅 때 **떠 있는 앱과 같은 커밋**에서 받아 `/opt/loadtest/lc-backend/loadtest` 에 둔다. `up --sha` 로 고른 커밋이면 시나리오도 그 커밋이다. 시나리오를 고친 뒤 다시 받거나 다른 브랜치로 받으려면 부하 생성기에서 돌린다.

```bash
sudo /opt/loadtest/refresh.sh                          # 앱과 같은 커밋으로 다시 받는다
sudo SCENARIO_REF=feat/xxx /opt/loadtest/refresh.sh    # 브랜치나 커밋을 골라 받는다
```

`mint-tokens.py` 가 없는 커밋이면 토큰 찍기를 건너뛴다. 광고 서빙 시나리오는 k6 안에서 `JWT_SECRET` 으로 직접 서명한다.

**시험 돌리기.** 데이터 넣기, 회차 실행, 지표 모으기는 lc-backend 가 갖는다. 환경을 띄운 뒤 lc-backend 폴더에서 같은 프로필로 돌린다. **그 폴더를 `develop` 으로 두고 돌린다.** 아래 스크립트가 `develop` 에 있고 `main` 에는 다음 릴리스까지 없다.

| 도메인 | 순서가 적힌 문서 | 실행 스크립트 |
|---|---|---|
| 광고 서빙 | lc-backend `docs/design/adserving/loadtest/adserving_부하_시험.md` 6장 | lc-backend `loadtest/adserving/run.sh` |

```bash
# lc-backend 에서. 접두사 lunchcatch-lt 가 기본이라 PROJECT 를 주지 않는다
AWS_PROFILE=me loadtest/adserving/run.sh seed 40000
AWS_PROFILE=me loadtest/adserving/run.sh prepare
AWS_PROFILE=me loadtest/adserving/run.sh run v1-run1 30000001
AWS_PROFILE=me loadtest/adserving/run.sh metrics <window 시작 ms> <window 끝 ms>   # run 이 출력한 window 줄의 두 값
```

**대시보드 남기기.** `down` 하면 Prometheus 데이터가 함께 사라진다. 회차가 끝나면 내리기 전에 lc-infra 에서 PNG 로 받는다. `--lt` 를 꼭 준다. 없으면 운영 계정용으로 돌아 멈춘다.

```bash
AWS_PROFILE=me ./scripts/loadtest-snapshot.sh --lt --label v1-run1 --from <window 시작 ms> --to <hold 끝 ms> --domain adserving
```

`--dash` 를 주지 않으면 대시보드를 모두 계층 순서(1. 개요 ~ 7. 테스트)로, 대시보드 높이 그대로 찍는다. 회차마다 폴더 하나를 둔다(lc-infra#191). 폴더 이름은 측정 회차면 `--label`, 진단 회차면 `--diag` 의 회차 이름이다. `--out <폴더>` 를 주면 `<폴더>/<회차 이름>/` 에, 주지 않으면 `loadtest-runs/<시각>_<회차 이름>/` 에 남는다. `--label` 을 생략한 측정 회차는 `loadtest-runs/<시각>/` 이다. 결과 문서 옆의 버전 폴더를 `--out` 으로 주면 측정 3회가 `v1-run1/`, `v1-run2/`, `v1-run3/` 으로 모인다. 회차 폴더 안은 아래와 같다. 대시보드는 그라파나의 폴더 이름과 제목을 그대로 쓰고 공백만 `_` 로 바꿔, 그라파나와 같은 계층 순서로 보인다.

```text
v1-run1/
  구간.txt
  traces.txt                      고른 트레이스 목록. 폴더 칸이 traces/ 의 폴더다
  dashboards/1._개요/시스템_개요.png
  dashboards/2._서비스/2._API.png
  traces/01-api-v1-feed/          trace.png, logs.png, logs.txt
  calltree/wall.png, cpu.png      진단 회차만. 앱 서버(서비스 lunchcatch)
  calltree/batch-wall.png, ...  진단 회차에 배치 프로파일(lunchcatch-batch)이 있을 때만(lc-infra #204)
  diff/wall.png, cpu.png          진단 회차에 --baseline 을 주었을 때만. 배치는 diff/batch-*.png, 기준 회차에도 배치가 있을 때만
  redis.txt                       진단 회차만
  diag-v1-run1-profile.tar.gz     진단 회차에 프로파일이 있을 때만(--diag v1-run1-profile 일 때)
```

한 도메인의 시험이면 `--domain adserving` 처럼 그 도메인을 준다. 도메인 폴더에서는 그 도메인만 찍고, 원인을 찾는 나머지 계층은 모두 찍는다. 진단 회차(`--diag`)도 측정 회차와 같은 대시보드를 찍고 `--domain` 을 함께 받는다(lc-infra#201). 원인을 볼 때 같은 회차의 서버 자원, RDB, 캐시를 견주려는 것이다. 진단 회차의 화면에는 프로파일링 비용이 섞여 측정 회차의 화면과 견주지 않는다. `--diag` 는 Call Tree 와 트레이스 화면을 브라우저 자동화 이미지(`scripts/diag-capture`)로 찍어, 이 기계에 Docker 가 떠 있어야 한다. 진단 회차는 `--no-traces` 를 주어도 Call Tree 를 찍어 늘 Docker 가 필요하다. 측정 회차도 트레이스를 찍으면 같은 이미지를 써 Docker 가 필요하고, 트레이싱이 없는 환경이거나 `--no-traces` 를 주면 측정 회차에는 Docker 가 필요 없다. 한 장만 받을 때는 `--dash lc-loadtest` 처럼 UID 를 준다.

진단 회차는 프로파일과 지표, 로그, 트레이스의 원본도 남긴다(lc-infra#199, #203). 환경을 내리면 Pyroscope, Prometheus, Loki, Tempo 의 기록이 함께 사라져, 다른 날 그 회차를 그라파나로 다시 보거나 다음 버전과 Diff 로 견줄 수 없기 때문이다. 측정 회차는 원본을 남기지 않는다.

| 파일 | 담는 것 |
|---|---|
| `diag-<회차>-profile.tar.gz` | 그 회차(`run` 꼬리표)의 cpu 와 wall 을 앱이 보낸 10초 묶음 그대로. 앱(`lunchcatch`)과 배치(`lunchcatch-batch`)를 서비스마다 나눠 둔다(lc-infra#204). 배치는 배치 서버에도 프로파일링을 붙인 회차(lunch-catch/lc-backend#1318 뒤)에만 있다. 앱 서버 여럿의 묶음은 Pyroscope 안에서 이미 합쳐져 하나로 남는다. 묶음의 합이 회차 전체의 합과 같은지 안의 `manifest.json` 에 적는다 |
| `metrics.json.gz` | 회차 구간의 지표 표본. 우리 대시보드의 식이 쓰는 지표 이름만 꺼낸다. k6 의 지연처럼 네이티브 히스토그램인 지표는 옮기지 못해 빠진다 |
| `logs.jsonl.gz` | 회차 구간의 앱과 배치의 경고와 오류 로그 |
| `traces/<번호>-<대상>/trace.json` | 고른 트레이스(`traces.txt`)마다 Tempo 원본 |

프로파일 파일의 이름은 `--diag` 의 회차 이름에서 끝의 `-profile` 을 떼고 `diag-` 와 `-profile.tar.gz` 를 붙인다. `--diag v1-run1-profile` 이면 `diag-v1-run1-profile.tar.gz`, `-profile` 로 끝나지 않는 `--diag v1-run1-tracing` 이면 `diag-v1-run1-tracing-profile.tar.gz` 다.

다시 볼 때는 이 기계의 로컬 구성(`observability/local`)에 원래 시각 그대로 넣는다. 그 회차 폴더를 주면 된다.

```bash
./scripts/loadtest-replay.sh <버전 폴더>/v1-run1-profile
```

- 관측 도구(그라파나, Prometheus, Loki, Tempo, Pyroscope, Alloy)만 다시 보기용 덮어쓰기(`compose.replay.yaml`)와 함께 띄우고 앱은 띄우지 않는다. 지난 시각의 데이터를 기본 설정은 지우거나 거절하거나 질의에서 빼서, 그것만 푼다. Prometheus 는 보관 기간을 사실상 두지 않고, Loki 는 지난 시각을 거절하지 않고 넣은 뒤 저장소로 흘려보내며, Pyroscope 는 넣기 제한(기본 1시간)을 풀고 예전 저장 구조(v1)로 돈다. Tempo 는 지난 시각의 스팬을 그 시각의 구간으로 찾게 하고 지우지 않는다(`tempo.replay.yaml`). 평소의 로컬 시험은 이 덮어쓰기를 쓰지 않는다
- 지표는 `promtool` 로 블록을 만들어 넣는다. 지난 시각으로 넣은 지표와 프로파일은 보이기까지 1 ~ 2분 걸리고, 프로파일은 cpu 와 wall 이 따로 보이기 시작한다
- 트레이스는 남긴 `trace.json` 을 Alloy 의 OTLP HTTP(호스트 14318)로 보내 Tempo 에 넣는다(#219). 판정 패널의 트레이스 링크가 그 구간에서 남긴 트레이스를 찾는다. 남기지 않은 트레이스는 나오지 않는다. 다시 보내는 트레이스가 테일 샘플링의 무작위 규칙에 걸리지 않게 다시 보기의 Alloy 는 나머지 비율을 100% 로 둔다
- 끝나면 그 회차 구간의 그라파나 주소를 출력한다
- 한 번에 한 회차만 본다. 다른 회차를 보려면 `observability/local` 에서 `docker compose -f compose.yaml -f compose.replay.yaml down -v` 로 내린 뒤 부른다.

앞 버전과 이 버전의 Diff flame graph 는 같은 환경에서 이어 재면 진단 회차의 캡처가 `--baseline` 으로 찍는다. 다른 날 쟀거나 환경을 내렸으면 두 진단 회차 폴더로 노트북에서 찍는다(lc-infra#209).

```bash
./scripts/loadtest-diff.sh <앞 버전의 진단 회차 폴더> <이 버전의 진단 회차 폴더> [--fixed <고친 함수>]...
```

- 회차 폴더는 진단 캡처가 만든 폴더면 된다. `--out` 을 주지 않아 이름 앞에 시각이 붙은 기본 폴더(`loadtest-runs/<시각>_<회차>`)도 된다. 회차 이름은 폴더 이름이 아니라 보관 파일(`diag-*-profile.tar.gz`)의 `manifest.json` 에서 읽는다
- 다시 보기 구성에 두 회차의 프로파일을 원래 시각 그대로 올리고, 앞 회차를 기준으로 한 Diff(wall, cpu)를 서비스마다 찍어 이 회차 폴더의 `diff/` 에 넣는다. 두 회차에 다 있는 서비스만 찍는다
- `--fixed` 는 그 버전에서 고친 함수다. 몫이 거의 변하지 않았어도 그 함수까지 가는 경로를 펼쳐 남긴다. 펼칠 진입점은 `--expand` 로 주거나, 주지 않으면 Call Tree 맨 위 진입점에서 wall 이 큰 3개를 고른다
- 다시 보기 구성의 Pyroscope 는 오래된 구간의 목록 질의도 인제스터에 묻는다(`-querier.query-store-after`). 기본(4시간)이면 지난 시각으로 올린 회차의 프로파일 종류 목록이 비어, Diff 화면이 wall 을 cpu 로 바꿨다

트레이싱을 켠 환경(Tempo 가 응답)이면 측정 회차와 진단 회차 모두 트레이스와 그 로그를 함께 찍는다(lc-infra#187). 판정과 고를 트레이스는 대시보드를 따른다(lc-infra#189). API 와 백그라운드 작업 대시보드의 "기준을 넘은" 패널이 회차 구간에 한 번이라도 낸 줄(API, 릴레이, 워커, cron 작업)마다, 그 패널에서 줄을 눌러 여는 트레이스 목록과 같은 트레이스를 오래 걸린 순으로 3개(`--trace-top` 으로 바꾼다) 고른다. 캡처는 대시보드의 판정식과 링크를 그대로 읽어, 대시보드를 고치면 캡처도 따라간다. 고른 목록은 `traces.txt`(폴더, 패널, 대상, 구간의 판정 최댓값, 걸린 시간, 트레이스 ID)에 남는다. 트레이스마다 트레이스 화면(`trace.png`), 그 트레이스 ID 가 든 로그 화면(`logs.png`)과 로그 글(`logs.txt`)이 나온다. 트레이스 하나마다 `traces/<번호>-<대상>/` 폴더에 이 셋이 함께 남는다. 대상은 대시보드와 그 줄의 이름이다(예: `api-v1-feed`, `background-serve-log-writer`). 로그는 Grafana 의 트레이스 → 로그 연결과 같은 쿼리(`{container=~"lunchcatch.*"} |= "<트레이스 ID>"`)로 찾는다. 진단 회차에서 `--trace <ID>` 를 주면 고르지 않고 그것만 찍는다. 트레이스 화면은 브라우저 자동화 이미지로 찍어 Docker 가 떠 있어야 한다. 찍지 않으려면 `--no-traces` 를 준다. 기준을 넘은 것이 없거나 앱이 기준 지표를 내보내지 않으면 `traces.txt` 에 그 이유만 남는다.

범위는 회차 시작부터 유지 구간 끝까지 한 번 준다. 대시보드는 램프업부터의 흐름을 보는 그래프다. 유지 구간의 결과 수치는 k6 요약과 `run.sh metrics` 에서 읽는다.

PNG 는 `loadtest-runs/` 에 쌓인다. 저장소에 올리지 않는다(gitignore).

**Grafana.** `status` 가 보여 주는 포트 포워딩 명령을 연 동안 `http://localhost:13000`. 사용자 `admin`, 비밀번호는 `status` 가 보여 주는 명령으로 읽는다. 운영과 같은 대시보드(부하 시험, API, 백그라운드 작업, 광고 서빙 포함)가 들어 있다.

**자동 정리 뒤(`MEMBER_HOURS` 를 준 경우).** VPC, 보안 그룹, S3, CloudFront, SSM 이 남는다. 거의 돈이 들지 않는다. `down` 을 한 번 부르면 다 지운다.

## 4. 비용

| | 시간당 | 4시간 시험 | 하루 켜 둠 | 한 달 켜 둠 |

## 5. 막히면

| 증상 | 할 일 |
|---|---|
| `AWS_PROFILE 을 준다` | 명령 앞에 `AWS_PROFILE=<자기 프로필>` 을 붙인다 |
| `origin/main 과 다르다` | `git pull`. 일부러 다른 코드로 띄우려면 `MEMBER_ALLOW_STALE=1` |
| `develop 에서 이미지를 올린 커밋을 못 찾았다` | lc-backend Actions 의 `이미지 공개` 실행이 성공한 적이 있는지 본다 |
| `ghcr.io/... 가 없다` | 그 커밋의 `이미지 공개` 실행이 아직 안 끝났거나 `develop` 을 거치지 않은 커밋이다 |
| `모듈화 전에 띄운 환경이 남아 있다` | 메시지의 명령 셋을 그대로 돌려 옛 환경을 지운 뒤 다시 `up` 한다 |
| `VcpuLimitExceeded` | 2절의 vCPU 한도를 올린다 |
| `이 계정에 운영이 떠 있다` | 운영을 올리는 계정이다(6절). 운영을 `./scripts/destroy.sh` 로 내린 뒤 띄운다 |
| 앱이 10분 안에 응답하지 않는다 | Grafana(Loki)나 `aws ssm start-session` 으로 앱 서버에 붙어 `docker logs lunchcatch-lt` 를 본다 |

## 6. 운영을 올리는 계정에서 띄우기

명령은 같다. 접두사가 어디서나 `lunchcatch-lt` 라 운영(`lunchcatch`)과 이름이 겹치지 않는다.

- 운영과 함께 띄우지 못한다. 운영이 떠 있으면 `up` 이, 이 한 벌이 떠 있으면 `apply.sh` 와 `start.sh` 가 멈춘다. 개발 서버는 함께 떠 있어도 된다
- `MEMBER_ALERT_EMAIL` 은 주지 않는다. 예산이 계정 전체 비용을 세서 맞지 않는다
