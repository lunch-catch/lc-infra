# 팀원 부하 시험 환경

백엔드 팀원이 자기 AWS 계정에 운영과 같은 인프라를 한 벌 띄워 각자 부하 시험을 한다 (lc-infra #11, #52). 필요한 것은 자기 계정 하나다. 계정이 나뉘어 서로의 시험이 영향을 주지 않는다.

```
 팀원 A 계정   k6 -> ALB -> 앱 2대 -> RDS, Valkey   (+ 배치 2대, 모니터링)
 팀원 B 계정   k6 -> ALB -> 앱 2대 -> RDS, Valkey   (+ 배치 2대, 모니터링)
 GitHub        GHCR 공개 패키지(ghcr.io/lunch-catch/lc-backend) <- 서버를 띄울 때 이미지를 로그인 없이 받아 간다
```

설계와 이유(운영과 무엇이 다른가, 선택적 자동 정리)는 `docs/system-design/런치캐치_팀원_부하시험환경.md` 에 있다.

## 1. 알아 둘 것

| 항목 | 내용 |
|---|---|
| 인프라 | 운영과 같은 Terraform 코드, 같은 서버 크기와 대수 |
| 앱 이미지 | lc-backend `develop` 에서 마지막으로 이미지를 올린 커밋. 다른 커밋은 `up --sha <커밋>` |
| 운영 모드 | 항상 `loadtest`. 결제는 토스 대신 앱 안의 목이 받고 지연 200ms 를 흉내 낸다 |
| 주소 | 도메인 없이 ALB 주소로 HTTP. TLS 처리 부하는 빠진다 |
| 데이터 | 빈 DB 로 시작한다 |
| 카카오 | 더미 값이다. 로그인은 시험용 토큰으로 대신한다 |
| 로그인 시도 제한 | IP 당 1분 10회. k6 한 대에서 로그인과 재발급을 돌리면 429 가 난다 |
| Bedrock | 쓰지 못한다. 템플릿 생성 API 는 시험에서 뺀다 |
| 시험 시간 | 제한 없다. 끝나면 `down` 으로 지운다. 켜 둔 동안 시간당 요금이 나간다(4절) |

## 2. 준비 (한 번)

| 필요한 것 | 확인 |
|---|---|
| 자기 AWS 계정 | 비용이 이 계정으로 나간다 |
| 그 계정의 관리자 IAM 사용자 | `AdministratorAccess`. 루트 키는 쓰지 않는다. 만드는 법은 아래 |
| 그 사용자의 CLI 프로필 | `aws configure --profile me`. 이름은 아무거나 되고, 아래 명령의 `me` 자리에 그 이름을 쓴다 |
| AWS CLI | `aws --version` |
| Terraform 1.15 | `terraform version`. `brew install hashicorp/tap/terraform` |
| git, curl, openssl, bash, python3 | macOS 와 Linux 는 기본으로 있다. python3 는 lc-backend 의 `run.sh` 가 원격 명령을 만들 때 쓴다. **Windows 는 WSL 에서 돌린다** |
| Session Manager 플러그인 | 부하 생성기와 Grafana 에 붙을 때. `brew install --cask session-manager-plugin` |
| EC2 vCPU 한도 14 이상 | 아래 명령. 낮으면 Service Quotas 에서 증가를 요청한다 (하루쯤 걸린다) |

```
aws service-quotas get-service-quota --service-code ec2 --quota-code L-1216C47A --query Quota.Value --profile me
```

**관리자 IAM 사용자와 프로필 만들기.** 이 환경은 VPC, RDS, IAM 역할까지 만들어서 관리자 권한이 필요하다.

1. 콘솔에 루트로 로그인해 IAM 으로 간다
2. 사용자를 만든다 (예: `lunchcatch-lt`). 권한은 "직접 정책 연결" 에서 `AdministratorAccess`
3. 그 사용자의 "보안 자격 증명" 에서 액세스 키를 만든다 (용도는 CLI)
4. `aws configure --profile me` 로 키를 넣는다. 리전은 `ap-northeast-2`
5. `aws sts get-caller-identity --profile me` 가 자기 계정 ID 를 보여 주면 된다

액세스 키는 `~/.aws/credentials` 에만 둔다. 저장소나 채팅에 붙이지 않는다. 오래 안 쓰면 키를 비활성화한다.

## 3. 쓰는 법

lc-infra 를 최신으로 받은 뒤 그 폴더에서 돌린다. `AWS_PROFILE` 은 꼭 준다. 엉뚱한 계정에 띄우지 않게 없으면 멈춘다.

```bash
git pull
AWS_PROFILE=me ./scripts/member-env.sh up       # 처음은 20분쯤. 끝나면 ALB 주소와 정리 시각을 보여 준다
AWS_PROFILE=me ./scripts/member-env.sh status   # 떠 있는 것, 정리 시각, 운영 모드, Grafana 접속 방법
AWS_PROFILE=me ./scripts/member-env.sh down     # 다 끝나면 지운다
```

| 옵션 | 뜻 |
|---|---|
| `up --sha <커밋>` | 그 커밋의 이미지로 띄운다. 짧은 SHA 도 된다. 없으면 `develop` 의 마지막 이미지 |
| `MEMBER_ALERT_EMAIL=<메일>` | 예산 알림(월 50 USD 기준)과 경보를 메일로 받는다. 처음 오는 확인 메일의 링크를 누른다 |
| `MEMBER_HOURS=<시간>` | 그 시간 뒤 AWS 가 서버, DB, 캐시, ALB, NAT 를 스스로 지운다. 노트북을 닫아도 돈다. 기본은 자동 정리 없음 |

`up` 을 다시 부르면 바뀐 코드만 반영한다. `MEMBER_HOURS` 를 주면 정리 시각을 지금부터 다시 세고, 안 주면 자동 정리를 없앤다. 정리된 뒤 `up` 을 부르면 지워진 것을 다시 만든다.

**부하 생성기.** `up` 이 보여 주는 `aws ssm start-session --target i-...` 로 붙는다. 시나리오와 토큰 발급은 lc-backend 의 `loadtest/` 를 따른다. 대상 주소는 `/opt/loadtest/env` 에 들어 있다.

시나리오는 부팅 때 **떠 있는 앱과 같은 커밋**에서 받아 `/opt/loadtest/lc-backend/loadtest` 에 둔다. `up --sha` 로 고른 커밋이면 시나리오도 그 커밋이다. 시나리오를 고친 뒤 다시 받거나 다른 브랜치로 받으려면 부하 생성기에서 돌린다.

```bash
sudo /opt/loadtest/refresh.sh                          # 앱과 같은 커밋으로 다시 받는다
sudo SCENARIO_REF=feat/xxx /opt/loadtest/refresh.sh    # 브랜치나 커밋을 골라 받는다
```

`mint-tokens.py` 가 없는 커밋이면 토큰 찍기를 건너뛴다. 광고 서빙 시나리오는 k6 안에서 `JWT_SECRET` 으로 직접 서명한다.

**시험 돌리기.** 데이터 넣기, 회차 실행, 지표 모으기는 lc-backend 가 갖는다. 환경을 띄운 뒤 lc-backend 폴더에서 같은 프로필로 돌린다. **그 폴더를 `develop` 으로 두고 돌린다.** 아래 스크립트가 `develop` 에 있고 `main` 에는 다음 릴리스까지 없다.

| 도메인 | 순서가 적힌 문서 | 실행 스크립트 |
|---|---|---|
| 광고 서빙 | lc-backend `docs/design/adserving/loadtest/adserving_부하_시험.md` 6장 | lc-backend `loadtest/adserving/run.sh` |

```bash
# lc-backend 에서. 접두사 lunchcatch-lt 가 기본이라 PROJECT 를 주지 않는다
AWS_PROFILE=me loadtest/adserving/run.sh seed 40000
AWS_PROFILE=me loadtest/adserving/run.sh prepare
AWS_PROFILE=me loadtest/adserving/run.sh run v1-run1 30000001
AWS_PROFILE=me loadtest/adserving/run.sh metrics <시작 ms> <끝 ms>
```

**대시보드 남기기.** `down` 하면 Prometheus 데이터가 함께 사라진다. 회차가 끝나면 내리기 전에 lc-infra 에서 PNG 로 받는다. `--lt` 를 꼭 준다. 없으면 운영 계정용으로 돌아 멈춘다.

```bash
AWS_PROFILE=me ./scripts/loadtest-snapshot.sh --lt --label v1-run1 --from <회차 시작 ms> --to <유지 구간 끝 ms>
```

`--dash` 를 주지 않으면 01 개요부터 06 광고 서빙까지 여섯 장을 대시보드 높이 그대로 찍는다. 한 장만 받을 때는 `--dash lc-loadtest` 처럼 UID 를 준다.

범위는 회차 시작부터 유지 구간 끝까지 한 번 준다. 대시보드는 램프업부터의 흐름을 보는 그래프다. 유지 구간의 결과 수치는 k6 요약과 `run.sh metrics` 에서 읽는다.

PNG 는 `loadtest-runs/` 에 쌓인다. 저장소에 올리지 않는다(gitignore).

**Grafana.** `status` 가 보여 주는 포트 포워딩 명령을 연 동안 `http://localhost:13000`. 사용자 `admin`, 비밀번호는 `status` 가 보여 주는 명령으로 읽는다. 운영과 같은 대시보드(05 부하 시험, 06 광고 서빙 포함)가 들어 있다.

**자동 정리 뒤(`MEMBER_HOURS` 를 준 경우).** VPC, 보안 그룹, S3, CloudFront, SSM 이 남는다. 거의 돈이 들지 않는다. `down` 을 한 번 부르면 다 지운다.

## 4. 비용

| | 시간당 | 4시간 시험 | 하루 켜 둠 | 한 달 켜 둠 |
|---|---|---|---|---|
| 1벌 | 약 0.4~0.6 USD | 약 2 USD | 약 10~15 USD | 약 300~430 USD |

청구는 자기 계정으로 간다. **자동 정리가 기본으로 꺼져 있어 `down` 을 잊으면 계속 나간다.** 하루 밤만 잊어도 10 USD 남짓이다. 잊을 것 같으면 `MEMBER_HOURS=4` 처럼 주거나 `MEMBER_ALERT_EMAIL` 로 예산 알림을 받는다.

## 5. 막히면

| 증상 | 할 일 |
|---|---|
| `AWS_PROFILE 을 준다` | 명령 앞에 `AWS_PROFILE=<자기 프로필>` 을 붙인다 |
| `origin/main 과 다르다` | `git pull`. 일부러 다른 코드로 띄우려면 `MEMBER_ALLOW_STALE=1` |
| `develop 에서 이미지를 올린 커밋을 못 찾았다` | lc-backend Actions 의 `이미지 공개` 실행이 성공한 적이 있는지 본다 |
| `ghcr.io/... 가 없다` | 그 커밋의 `이미지 공개` 실행이 아직 안 끝났거나 `develop` 을 거치지 않은 커밋이다 |
| `모듈화 전에 띄운 환경이 남아 있다` | 메시지의 명령 셋을 그대로 돌려 옛 환경을 지운 뒤 다시 `up` 한다 |
| `VcpuLimitExceeded` | 2절의 vCPU 한도를 올린다 |
| `이 계정에 운영이 떠 있다` | 운영을 올리는 계정이다(6절). 운영을 `./scripts/destroy.sh` 로 내린 뒤 띄운다 |
| 앱이 10분 안에 응답하지 않는다 | Grafana(Loki)나 `aws ssm start-session` 으로 앱 서버에 붙어 `docker logs lunchcatch-lt` 를 본다 |

## 6. 운영을 올리는 계정에서 띄우기

명령은 같다. 접두사가 어디서나 `lunchcatch-lt` 라 운영(`lunchcatch`)과 이름이 겹치지 않는다.

- 운영과 함께 띄우지 못한다. 운영이 떠 있으면 `up` 이, 이 한 벌이 떠 있으면 `apply.sh` 와 `start.sh` 가 멈춘다. 개발 서버는 함께 떠 있어도 된다
- `MEMBER_ALERT_EMAIL` 은 주지 않는다. 예산이 계정 전체 비용을 세서 맞지 않는다
