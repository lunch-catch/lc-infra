# 팀원 개발 서버 접근

팀원 7명이 자기 AWS 계정에서 **역할 전환(Switch Role)** 으로 우리 계정(762794225116)의 개발 서버에 들어온다 (lc-infra #10). 키를 나눠 주지 않고, 자격 증명은 최대 4시간짜리 임시다.

할 수 있는 것은 넷이다.

| 무엇 | 어떻게 |
|---|---|
| 개발 앱 로그 (30일) | Grafana, 콘솔 CloudWatch, `dev-logs` 스크립트 |
| 개발 지표 | Grafana |
| 개발 DB | `dev-db` 스크립트로 `localhost:13306` |
| 로컬에서 Bedrock 부르기 | [팀원 로컬 Bedrock](팀원-로컬-Bedrock.md) |

다른 비밀값, S3, 서버 셸 접속은 막혀 있다. DB 계정 `team` 은 데이터 읽기와 쓰기만 되고 테이블 구조는 못 바꾼다.

설계와 이유는 `docs/system-design/런치캐치_개발서버.md` 10, 11장에 있다.

## 1. 준비 (한 번)

| | macOS | Windows (PowerShell) |
|---|---|---|
| AWS CLI | `brew install awscli` | `winget install -e --id Amazon.AWSCLI` |
| 플러그인 | `brew install --cask session-manager-plugin` | `winget install -e --id Amazon.SessionManagerPlugin` |
| 설정 파일 | `~/.aws/config` | `%UserProfile%\.aws\config` |
| 스크립트 실행 허용 | 필요 없음 | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` (한 번) |

Windows 의 `%UserProfile%` 는 명령이 아니라 내 사용자 폴더(보통 `C:\Users\<윈도우 사용자 이름>`)를 가리키는 이름이다. 파일 탐색기 주소창과 명령 프롬프트에서는 그대로 쓰고, PowerShell 에서는 `$env:USERPROFILE` 로 쓴다. 예: `notepad "$env:USERPROFILE\.aws\config"`. 메모장으로 저장할 때 이름이 `config.txt` 가 되지 않게 "파일 형식" 을 "모든 파일" 로 둔다.

1. 자기 계정에 **IAM 사용자**로 로그인할 수 있어야 한다. 루트 사용자(이메일 로그인)는 역할 전환을 못 한다. 그 사용자에게 `sts:AssumeRole` 권한이 있어야 하고 `AdministratorAccess` 면 이미 있다
2. 그 IAM 사용자의 액세스 키를 자기 프로필(예: `me`)로 넣는다. `aws configure --profile me`
3. `config` 에 아래를 더한다. `source_profile` 은 2번의 프로필 이름이다

```ini
[profile lunchcatch-dev]
role_arn = arn:aws:iam::762794225116:role/lunchcatch-dev-team
source_profile = me
region = ap-northeast-2
duration_seconds = 14400
```

4. `aws sts get-caller-identity --profile lunchcatch-dev` 가 `assumed-role/lunchcatch-dev-team/...` 을 보이면 된다
5. `git clone https://github.com/lunch-catch/lc-infra.git`. Windows 는 설치한 뒤 터미널을 새로 연다. 새 PATH 는 새 창에서만 잡힌다

## 2. Grafana (로그와 지표)

https://grafana.dev.lunchcatch.com 에 `team` 계정으로 로그인한다. 보기 권한이다. 비밀번호는 직접 읽는다 (Windows 도 같다).

```bash
aws ssm get-parameter --name /lunchcatch/dev/grafana-team-password --with-decryption --query Parameter.Value --output text --profile lunchcatch-dev
```

- 대시보드는 운영과 같은 01 ~ 06 에 개발 전용 07(개발 앱 로그)이 있다
- 개발에 없는 것(RDS, ALB, 배치 서버, 호스트 지표, Loki)을 보는 패널은 비어 보인다
- 로그는 07 이나 Explore 에서 CloudWatch 를 골라 Logs Insights 쿼리로 본다
- 로그인을 다섯 번 틀리면 그 계정이 잠시 막힌다

## 3. 콘솔에서 로그 보기

자기 계정 콘솔에 IAM 사용자로 로그인한 뒤 아래 링크를 연다. 한 번 넘어오면 오른쪽 위 메뉴에 `lunchcatch-dev` 가 남는다. CloudWatch -> 로그 그룹 `/lunchcatch/dev/app` 에서 검색, Live Tail, Logs Insights 를 쓴다.

```
https://signin.aws.amazon.com/switchrole?account=762794225116&roleName=lunchcatch-dev-team&displayName=lunchcatch-dev
```

## 4. 스크립트 (로그와 DB)

lc-infra 폴더에서 돌린다.

```bash
# macOS
./scripts/dev-logs.sh                     # 최근 10분부터 실시간
./scripts/dev-logs.sh 2h ERROR            # 최근 2시간의 ERROR 만
./scripts/dev-db.sh                       # 열어 둔 동안 localhost:13306 으로 붙는다. 접속 정보를 출력한다
```

```powershell
# Windows (PowerShell)
.\scripts\dev-logs.ps1
.\scripts\dev-logs.ps1 2h ERROR
.\scripts\dev-db.ps1
```

Windows 판(`*.ps1`)은 macOS 판과 같은 일을 한다. 실행 정책 때문에 막히면 `powershell -ExecutionPolicy Bypass -File .\scripts\dev-db.ps1` 로 돌린다.

## 5. 막히면

| 증상 | 할 일 |
|---|---|
| `AccessDenied` (역할 전환) | 루트가 아니라 IAM 사용자로 했는지, 계정 ID 를 담당자에게 보냈는지 본다 |
| `ExpiredToken` | 4시간이 지났다. 명령을 다시 돌리면 새로 받는다 |
| `SessionManagerPlugin is not found` | 1절의 플러그인을 설치하고 터미널을 새로 연다 |
| Grafana 로그인이 막힌다 | 다섯 번 틀려 잠겼다. 잠시 뒤 다시 한다 |
